# Yange 2.0 WebMCP Technical Demo — 2:52 Target

## Recording setup

- Record in landscape at 1080p or higher. Use 80–90% browser zoom so the mission and proof drawer remain legible.
- Turn off notifications and hide bookmarks. Keep the cursor slow and intentional.
- Open two tabs only: the tested public Pinterest outfit Pin and `https://web-jet-one-21.vercel.app/?view=mission`.
- Start a new mission before recording and use an inspiration look that visibly maps to seeded wardrobe pieces.
- Confirm the Yange badge says **Browser agent: registered**. If it says **unsupported**, stop; that take cannot prove WebMCP.
- Keep the core agent sequence continuous. Small cuts are fine before the first tool call and after the receipt, but do not cut across the pending human handoff or approval boundary.

## Shot-by-shot script

### 0:00–0:12 — The missing bridge

**Picture:** Begin on the public Pinterest Pin. Hold for two seconds, then show the browser-agent prompt.

**Say:**

> “The web can understand this outfit, and Yange understands the clothes I actually own. Before WebMCP, I still had to connect those worlds by screenshot, upload, and explanation.”

### 0:12–0:30 — Native open-web handoff

**Picture:** Ask: **“Bring this look home with Yange.”** Let the agent visibly choose `import_current_outfit_inspiration`. Show Yange opening with the original source attribution and image.

**Say:**

> “Now the browser agent calls one semantic Yange tool. It carries the Pinterest image and its source directly into Yange—without cookies, hidden scraping, or a screenshot. When Pinterest blocks browser delivery, Yange uses a locked-down same-origin importer, validates the real image, and keeps attribution visible.”

### 0:30–0:45 — Human-reviewed Look DNA

**Picture:** Show the extracted palette, silhouette, key pieces, layering, and occasion cues. Press **Save this Look DNA**.

**Say:**

> “Gemini interprets the visual ambiguity, but it does not invent clothes I own. I review and save only the structure of the look. That visible action resolves the same pending WebMCP import.”

### 0:45–1:01 — Tools shaped around outcomes

**Picture:** On Mission, open **Technical proof · semantic tools and visible receipts**. Briefly show the current phase-valid tools; then close it and run the wardrobe inspection through the agent.

**Say:**

> “This is not a tool wrapped around every button. Yange exposes eight outcome-level tools, and only the tools valid for the current phase exist. The agent receives garment names, state, and evidence quality—not private photos or my event ledger.”

### 1:01–1:25 — Where the internet ends

**Picture:** Let inspection reveal the missing fact. Have the agent call `request_missing_evidence`. Hold on **The internet ends here. Your wardrobe begins.** Do not answer immediately.

**Say:**

> “Then the agent reaches something no webpage can know: whether this garment is physically here, or whether its care evidence is trustworthy. The tool call stays genuinely pending while Yange hands control to me.”

### 1:25–1:42 — The same call resumes

**Picture:** Confirm the garment or care evidence in the visible interface. Show **Evidence received** and briefly reopen Technical Proof so the changed tool set is visible.

**Say:**

> “I supply the physical truth. The same call resumes with person-sourced evidence, and Yange replaces the evidence tool with the next valid action. The agent did not guess, and I did not have to restart the task.”

### 1:42–2:00 — Three safe futures

**Picture:** Ask the agent to simulate. Show all three cards together: **wear now**, **wash first**, and **verified fallback**.

**Say:**

> “Deterministic policy now compares exactly three futures before changing anything: wear now, wash first, or use a verified fallback. Gemini can explain ambiguity; policy decides what is actually feasible.”

### 2:00–2:22 — Consent outside the agent

**Picture:** Prepare one feasible path. Pause on **Prepared, not committed**. Show that the person must press **Approve this exact plan**, then press it.

**Say:**

> “Preparation is not permission. Approval is not even accepted as a tool argument. It lives only in this visible interface and is bound to this exact plan and wardrobe revision. If the wardrobe changes, the plan fails closed as stale.”

### 2:22–2:38 — Commit once, prove it

**Picture:** Let the agent call `commit_approved_plan`. Hold on the shared receipt: operation ID, cited evidence, committed action, and replay-safe status. Open Technical Proof one last time.

**Say:**

> “Only after my approval can the agent commit. The effect happens once, and both of us receive the same durable receipt. A retry returns that receipt instead of repeating the wardrobe change.”

### 2:38–2:52 — The product still has a heart

**Picture:** Cut to the live wardrobe with Style Aura moving behind it. End on the Yange name and live URL.

**Say:**

> “WebMCP carries the work, but Yange remains personal. Style Aura changes gradually as confident, repeated wears teach it my colours. I did not add WebMCP for eligibility; I used it to complete the experience Yange was always meant to become. In Luganda, *yange* means mine.”

## Do not show

- A tour of every Yange tab.
- Google Cloud dashboards or architecture slides in this WebMCP demo.
- All eight tool definitions one by one.
- A manual-only mission while claiming it is agent-driven.
- A Browser agent badge that says `unsupported`.
- A successful direct-import claim if the recorded source actually required manual upload.

## The five frames judges must remember

1. The outfit page invoking `import_current_outfit_inspiration`.
2. Attributed Look DNA inside Yange.
3. A WebMCP execution visibly waiting for physical truth.
4. Human approval outside the agent’s arguments.
5. A shared replay-safe receipt, followed by Style Aura.
